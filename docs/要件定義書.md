# ReFlareバンド生成要件定義書

## 1. 目的・概要

アンケート結果のCSVファイルを入力とし、スコアに基づいてバンド編成を行い、結果を新規CSVファイルに出力する。

- **入力**: 応募者アンケート結果のCSV
- **処理**: バンド生成アルゴリズムによる編成とスコア計算
- **出力**: 編成結果およびスコアを格納したCSV（1バンド1行形式）

---

## 2. 入力仕様

### 2.1 CSVデータ構造

入力CSVの列は以下のとおりとする。

| 列名 | 説明 |
|------|------|
| id | 応募者ID（一意） |
| name | 氏名 |
| university | 大学名 |
| experience_years | 経験年数（数値） |
| first_part | 第1希望パート（Lead / 1st / 2nd / 3rd / Bass / Perc. のいずれか） |
| second_part | 第2希望パート |
| third_part | 第3希望パート |
| can_arrange | アレンジ可否。「はい」または「いいえ」の文字列 |
| genre | 希望ジャンル（1人1ジャンル） |

### 2.2 パートの取り得る値

- Lead, 1st, 2nd, 3rd, Bass, Perc.

---

## 3. 出力仕様

### 3.1 基本方針

- **1バンド1行**でメンバー情報をまとめる。
- 各バンドの**スコア**を列として含める。

### 3.2 出力CSV列（案）

**バンド共通情報**

| 列名 | 説明 |
|------|------|
| band_index | バンド番号（1, 2, 3, …） |
| band_size | バンド人数（5 または 6） |
| band_score_total | バンド総合スコア（U + E + W_part + W_genre） |
| score_U | 大学多様性スコア |
| score_E | 経験年数多様性スコア |
| score_W_part | 希望パート一致スコア |
| score_W_genre | ジャンルスコア |

**メンバー情報（最大6人分）**

- 各メンバーごとに以下を列として持つ（member1_〜member6_）。5人バンドの場合は member6_ は空欄とする。
  - memberN_id, memberN_name, memberN_university, memberN_experience_years  
  - memberN_assigned_part（割り当てパート）  
  - memberN_first_part, memberN_second_part, memberN_third_part  
  - memberN_can_arrange, memberN_genre  

---

## 4. バンド構成

### 4.1 パート構成

- **通常**: Lead, 1st, 2nd, 3rd, Bass, Perc. の **6人**で1バンド。
- **人数不足時**: Perc. なしの **5人**バンドとする（最後の数バンドだけ5人にする運用）。

### 4.2 バンド数の決め方

- 応募者総数に応じて、6人バンドを優先し、余りが出る場合は**最後の数バンドだけを5人**とする。
- **5人未満のバンドは作らない**（調整により必ず 5 または 6 人とする）。

例: 34人の場合 → 6人×4バンド + 5人×2バンド など。

---

## 5. 探索方針

### 5.1 全順列探索が不可能であること

応募者数を N とするとき、並び順の候補は N! 通りある。  
N=34 のとき 34! は約 2.95×10^38 であり、全探索は現実的に不可能である。

### 5.2 採用する探索手法

- **ランダムシャッフル多回試行**  
  応募者リストをランダムにシャッフルし、先頭からバンドサイズ（6,6,…,5,5）で区切って編成候補を生成する。  
  ハード制約を満たす編成についてのみスコアを計算し、**所定回数（例: 1万〜10万回）のうち最もスコアの高い編成を採用**する。
- **ローカルサーチ（任意・推奨）**  
  上記で得た最良編成を初期解とし、異なるバンド間でメンバーを1人ずつ入れ替えてスコアが改善するなら採用する、という操作を繰り返し、近傍探索で解を改善する。

---

## 6. パート割り当て方針

- **各バンドについて**、メンバー6人（または5人）が決まった後に、**パート割り当てを最適化**する。
- 6人バンドでは割り当て候補は高々 6! = 720 通りであるため、**希望パート制約を満たす割り当てのうち、W_part が最大となる割り当て**を採用する。
- 「希望じゃないパート」には割り当てない（ハード制約。後述）。

---

## 7. スコアリング

### 7.1 バンドスコアの構成

1バンドのスコア = **U + E + W_part + W_genre**（いずれもスコア計算対象となるバンドのみ）。

### 7.2 各スコアの定義

| 記号 | 名称 | 計算式 | 備考 |
|------|------|--------|------|
| U | 大学の多様性 | (バンド内の大学の種類数 / バンド人数) × 3 | 人数は 5 または 6 |
| E | 経験年数の多様性 | s / (1 + s) × 2 | s = 経験年数の標準偏差。ばらつきが大きいほど高くなる |
| W_part | 希望パート一致度 | (メンバーごとの加点合計 / バンド人数) × 2 | 第一希望+3、第二希望+2、第三希望+1。**案A**（合計を人数で割り、重み2をかける） |
| W_genre | ジャンルの相性 | (バンド内で最多希望人数のジャンルを希望している人数 / バンド人数) × 1 | 1人1ジャンルとして、最多ジャンルの人数割合 |

### 7.3 順列（編成）のスコア

- 各バンドがハード制約を満たす場合のみ、そのバンドのスコアを合計に含める。
- **全バンドのスコアの合計**を、その編成（順列）のスコアとする。
- 探索では、この合計が**最大となる編成**を採用する。

---

## 8. ハード制約

以下のいずれかに該当するバンドが1つでも含まれる編成は、スコア計算の対象外（無効な編成）とする。

1. **アレンジャー不在**  
   `can_arrange` が「はい」のメンバーが**1人もいない**バンドが含まれる編成は除外する。
2. **5人バンドに Perc. が含まれる**  
   人数が5人のバンドに Perc. が割り当てられている編成は除外する。
3. **希望外パートの割り当て**  
   第1希望・第2希望・第3希望のいずれにも含まれていないパートを割り当てられているメンバーがいるバンドが含まれる編成は除外する。  
   （第三希望までに含まれるパートのみ割り当て可能とする。）

---

## 9. 用語・補足

- **can_arrange**: CSV 上は「はい」または「いいえ」の文字列。各バンドに「はい」が最低1人必要。
- **希望じゃないパート**: first_part, second_part, third_part のいずれにも含まれていないパート。
- **genre**: 1人1ジャンル。バンド内で最多の希望ジャンルを用いて W_genre を計算する。
