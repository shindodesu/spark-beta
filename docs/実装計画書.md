## 4. データフロー（処理の流れ）

1. **入力**  
   CLI で指定した入力CSVを読み、応募者リスト（および型チェック・バリデーション）を得る。
2. **バンドサイズ計算**  
   応募者数から、6人バンド数と5人バンド数を決定する。
3. **探索**  
   - ランダムシャッフルを所定回数実行。  
   - 各試行: シャッフル → バンド分割 → 各バンドのパート割り当て → ハード制約チェック → 全バンド有効ならスコア合計を計算し、これまでの最大と比較。  
   - 最大スコアの編成を保持。
4. **ローカルサーチ（オプション）**  
   保持した編成を初期解に、バンド間の1人入れ替えで近傍探索し、改善が止まるまで繰り返す。
5. **出力**  
   最終編成について、1バンド1行形式でスコア列・メンバー情報を出力CSVに書き出す。

## 5. スコア・制約の実装メモ（要件定義書との対応）

- **U**: バンド内の大学の種類数 / バンド人数 × 3  
  → メンバーの `university` を集計し、ユニーク数で計算。
- **E**: s = 経験年数の標準偏差。E = (s / (1 + s)) × 2  
  → `experience_years` の配列から標準偏差を算出。
- **W_part**: メンバーごとに割り当てパートが第1希望+3、第2+2、第3+1。合計をバンド人数で割り、×2。  
  → パート割り当て結果と各メンバーの first/second/third_part を照合。
- **W_genre**: バンド内で最多希望人数のジャンルの人数 / バンド人数 × 1。  
  → メンバーの `genre` を集計し、最大出現回数で計算。
- **ハード制約**  
  - 各バンドに `can_arrange === "はい"` が最低1人。  
  - 5人バンドでは割り当てパートに Perc. を含めない（5人時は Perc. を割り当て候補から外す）。  
  - 割り当てパートは必ず first_part / second_part / third_part のいずれか。

## 6. テスト方針

| レベル | 内容 |
|--------|------|
| 単体 | スコア計算（U, E, W_part, W_genre）を固定バンドで検証。ハード制約チェックを「違反あり」「違反なし」のケースで検証。パート割り当てを小さい例（例: 6人・希望が決まったケース）で検証。 |
| 結合 | 少人数（例: 12人）の入力CSVで、シャッフル回数を少なめにした探索から出力CSVまで一括実行し、列数・スコアの妥当性を目視または簡易スクリプトで確認。 |
| リグレッション | 固定シードで同じ入力から同じ出力が得られることを確認（再現性）。 |
